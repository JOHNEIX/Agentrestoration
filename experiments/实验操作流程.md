# AgentRestoration 实验操作流程

版本：v0.1  
日期：2026-11-17  
适用环境：当前 Windows 工作区 `F:\Agentrestoration`  
实验背景与指标定义见 [实验设计说明](实验设计说明.md)，历史结果见 [实验记录](实验记录.md)。

## 1. 先确定是查结果还是重新实验

| 目的 | 应执行的操作 | 是否发送真实 API 请求 |
| --- | --- | --- |
| 阅读历史结果 | 打开实验记录、结果 JSON 和对应任务目录 | 否 |
| 核对源码规则 | 运行 pytest 或阅读源文件 | 否 |
| 检查输入配对 | 运行 `verify_pairs.py` | 否 |
| 验证 Restormer 能执行 | 运行 `tool_smoke.py` | 否，只有本地推理 |
| 生成校准配置 | 运行 `experiments/runner.py calibrate` | 否，但使用本地检测权重 |
| 重新进行四组实验 | 运行 `experiments/runner.py run` | 是 |
| 重新生成报告 | 运行 `report.py` | 否，但会覆盖报告及人工复核表 |

已有 48 组结果可直接阅读，不需要为了看结果重新运行实验。下面的新实验步骤是操作说明，本次写文档没有重新发送请求。

## 2. 查阅已有实验的顺序

1. 阅读 [实验设计说明](实验设计说明.md)，确认四组差异与试运行边界。
2. 阅读 [实验记录](实验记录.md)，查看汇总及指标缺失说明。
3. 打开 `experiments/results.json`，选择一行，找到 `directory` 对应的任务目录。
4. 读取任务 `record.json` 的 `output`，这才是该组被评价的最终输出。A/B 通常为候选图片；C/D 成功为 `final.png`，未通过为 `original_normalized.png`。
5. 同时查看原图、最终输出、所有被拒候选及验证理由；不要只看最终图来判断是否误拒绝。

不需要手工按目录名推测实验归属，`results.json` 已将场景、组别和任务目录关联起来。运行目录还包含额外调试和工具测试任务，它们不是额外的四组实验样本。

## 3. 新实验前必须归档

当前脚本使用固定文件名，行为如下：

| 命令 | 会写入或覆盖的内容 |
| --- | --- |
| `experiments/runner.py manifest` | `experiments/manifest.json` |
| `verify_pairs.py` | `experiments/pairing_checks.json` |
| `experiments/runner.py calibrate` | 校准控制图、`calibration.json`；成功时写 `frozen_config.json` |
| `experiments/runner.py run` | 从空的结果列表开始写 `results.json`，不是自动续跑；结束时重建 `human_review.csv`；生成失败时写 `results.partial.json` |
| `report.py` | `experiments/实验记录.md`，以及 `experiments/human_review.csv` |
| pytest 的 XML 参数 | 参数指定的测试结果文件 |

**`report.py` 会把人工复核表重新写成待复核状态。已经填过标签后，不能直接运行它覆盖原表。**应先保留已填写的表；报告脚本目前也不会把人工标签计算成新的人工指标。

可在 PowerShell 中先执行以下归档。示例只复制项目资料，不包含 `api.txt`、`.env` 或整个虚拟环境，也不会移动或删除原数据：

```powershell
Set-Location 'F:\Agentrestoration'
$archiveId = Get-Date -Format 'yyyyMMdd_HHmmss_fff'
$archiveRoot = Join-Path $PWD "experiment_archives\$archiveId"
New-Item -ItemType Directory -Path $archiveRoot | Out-Null
Copy-Item -LiteralPath @('.\experiments', '.\src', '.\scripts', '.\tests', '.\configs') -Destination $archiveRoot -Recurse
Copy-Item -LiteralPath @('.\README.md', '.\requirements.lock.txt', '.\pyproject.toml') -Destination $archiveRoot
```

权重和作者代码通常不必重复复制大文件，但要保留 `weights/sources.json`、`third_party/Restormer/source.json`，并确认相关权重与代码哈希可取得。需要长期离线复现时，再单独保留这些资产。原有 `experiments/runs` 目录不得删除，归档的结果表仍通过目录路径引用其中图片。

```powershell
Copy-Item -LiteralPath '.\weights\sources.json' -Destination (Join-Path $archiveRoot 'weight_sources.json')
Copy-Item -LiteralPath '.\third_party\Restormer\source.json' -Destination (Join-Path $archiveRoot 'restormer_source.json')
```

新实验应记录归档 ID。该归档能保留现在的源码，不能补出第一次试运行启动时没有保存的历史代码快照。

## 4. 准备环境与资产

以下命令均在工作区根目录执行，不需要激活环境：

```powershell
Set-Location 'F:\Agentrestoration'
$env:PYTHONPATH = Join-Path $PWD 'src'
$env:PYTHONUTF8 = '1'
$env:PIP_CACHE_DIR = Join-Path $PWD '.cache\pip'
$env:TEMP = Join-Path $PWD '.cache\temp'
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Path $env:TEMP -Force | Out-Null
.\.venv\Scripts\python.exe --version
```

已有本机环境不需要重新安装。其他机器安装步骤参见 [README](../README.md)，依赖以 `requirements.lock.txt` 为参考。本次实际使用 CPU 版 PyTorch，不把结果当作 RTX 3060 的 GPU 性能数据。

检查 `weights/yolo11n.pt`、Restormer 去噪权重和作者网络定义已经存在。若需下载，可运行 `scripts/setup_assets.py`；它需要网络，并可能更新作者代码版本，因此应在版本冻结前执行，不能在正式一轮实验中途替换资产。

检查本地 `api.txt` 或环境变量中两组凭据已配置。模型与地址见 `configs/default.json` 和 `experiments/frozen_config.json`。不要把凭据复制到实验文档、截图、归档或结果表。

## 5. 先验证程序和专用工具

```powershell
.\.venv\Scripts\python.exe -m pytest -q --junitxml=tests/results.xml
.\.venv\Scripts\python.exe experiments/tool_smoke.py
```

pytest 用模拟适配器验证错误分支，不发送真实修复请求。`tool_smoke.py` 使用一张已知噪声图实际执行 Restormer，将独立推理记录写到 `experiments/runs`，并写 `experiments/tool_smoke.json`。它不执行完整在线 VLM 接受流程，所以工具输出存在不等于整个系统已经接受结果。

若测试失败、权重无法加载或推理失败，先解决问题，不带着未知故障启动完整四组实验。已有历史通过记录可供参考，但不能代替新版本的验证。

## 6. 生成并检查样本清单

```powershell
.\.venv\Scripts\python.exe experiments/runner.py manifest
.\.venv\Scripts\python.exe experiments/verify_pairs.py
```

检查 `experiments/manifest.json` 中恰有 8 个校准和 12 个测试场景，场景 ID 不重复、两集合不相交，同名参考图存在且哈希已记录。选取顺序与种子详见实验设计说明。

检查 `pairing_checks.json`，关注是否存在数值不一致。若发现配对问题，应在真实实验开始前处理并重新归档清单，不能跑完后根据结果好坏替换测试图片。

清单中的 `pairing` 字段记录的是清单生成时的同名和尺寸检查；后续数值检查单独保存在 `pairing_checks.json`，不会自动修改该字段。

## 7. 校准并冻结本轮配置

```powershell
.\.venv\Scripts\python.exe experiments/runner.py calibrate
```

检查以下内容：

- `experiments/calibration.json` 的状态、有效匹配对象数和各场景记录。
- `experiments/frozen_config.json` 的位置、宽高比、检测参数、任务与模型配置。
- 校准脚本是否正常结束。若失败，不能把上一次遗留的 `frozen_config.json` 当作本轮校准成功的证据。

当前脚本只做亮度控制校准，匹配对象达到 3 个仅表示程序允许生成配置。本次历史校准只有 3 个匹配，仍属于试运行。若准备正式报告，应先补充校准样本和人工错误标注，再固定阈值，不使用 12 张测试图调参。

冻结后保留源码、依赖、配置、提示词和资产信息。本轮运行期间不改源码、不重跑校准、不替换模型权重；否则应另建版本并重新实验。

## 8. 先做一张校准图的真实联调

已有最近成功记录且代码、配置未变时，可以跳过。需要联调时，应使用校准集图片，避免提前依据测试结果调参。以下命令会发送真实图片并产生 API 调用：

```powershell
$env:PYTHONPATH = Join-Path $PWD 'src'
.\.venv\Scripts\python.exe -m agentrestoration.cli 'F:\cvlab\datasets\test-data\denoising_testsets\CBSD68_25\291000.png' --task gaussian_denoising --config experiments/frozen_config.json
```

核对结果目录中的请求、次数、候选、判断器路线和最终状态。`--task gaussian_denoising` 表示已知合成高斯去噪任务；当前默认 `auto` 不把未知噪声直接送给专用高斯权重。

联调任务不计入四组测试表。若接口出错，先查看脱敏错误和配置，不反复新建任务来绕过每任务额度。

## 9. 正式启动本轮四组试运行

确认归档、样本和冻结配置无误后执行：

```powershell
.\.venv\Scripts\python.exe experiments/runner.py run
```

实际顺序为：读取清单 → 跳过校准样本 → 第一张测试图 A、B、C、D → 第二张 A、B、C、D → 直到 12 张结束。当前不并行执行四组。

每组先完成生成流程，再对最终输出执行统一离线结构检查和 VLM 比较，最后计算可用的参考图指标并写一行结果。当前脚本将测试任务显式设为高斯去噪。

终端中的 `baseline_completed` 只是 A/B 生成结束；`completed` 表示 C/D 在线明确接受；`needs_review` 表示没有候选被接受，保留原图；`execution_failed` 表示执行问题。不能将四种状态一律称为修复成功。

编辑请求最多两次、工具流程最多一次；VLM 分析和评价不属于编辑额度，但请求仍应计入实际成本。独立离线评价不改变该任务已完成的在线决策，也不包含在 `elapsed_seconds` 中。

## 10. 中断、报错与重跑

当前实验脚本没有自动续跑功能，重新运行会从头生成，不会根据已有结果跳过场景。新的 `results.json` 可能逐步覆盖旧结果，因此先归档，再决定是否开始一轮新的实验。

生成流程返回 `execution_failed` 时，驱动会保存已完成行到 `results.partial.json` 并停止。若异常发生在后续离线评价或指标计算阶段，则不保证生成同样的 partial 文件：应同时检查已有 `results.json` 和最后任务目录，不把缺失行当成成功或零质量。

中断时已发请求可能已经执行，预算不能清零。任务事件和原目录应保留，不手工伪造成功状态。任务是否生成了图片、是否完成在线判断、是否完成离线评价，应分别核对。

## 11. 汇总结果并进行完整性检查

**在人工作业开始前**生成汇总：

```powershell
.\.venv\Scripts\python.exe experiments/report.py
```

该命令更新 `实验记录.md` 并生成待复核 CSV。然后检查：

1. `results.json` 有 48 行、12 个不同场景，每个场景恰有 A/B/C/D 一行。
2. 每行编辑计数不超过 2、工具计数不超过 1；计数和任务事件可对应。
3. 每行 `directory` 存在，任务记录与最终输出可以打开。
4. C/D 中只有接受任务生成 `final.png`；未通过结果应指向原图。A/B 的接受状态为空。
5. PSNR/SSIM 为空时有尺寸不一致等原因，不将空值填成 0，也不任意拉伸图片补算。
6. 保留有效样本数、失败数、无法确认数和人工待复核数，不能仅展示成功案例。

当前历史结果为 48 行、62 次编辑请求、5 次工具启动；这些数字只用于核对已有这一轮，不能要求新一轮随机生成必须得到相同数字。

## 12. 人工复核怎么做

打开 `experiments/human_review.csv`，先另存一份，例如 `human_review_labeled_<轮次>.csv`，在副本中填写。不要让 `run` 或 `report.py` 覆盖已填写文件。

每个场景按以下顺序查看：有噪声的原图 → 最终输出 → 干净参考图 → 所有候选及拒绝原因。参考图用于评价，不反向修改本轮已经冻结的程序。

| 列 | 建议填写方式 |
| --- | --- |
| `scene`、`group`、`directory` | 保留程序生成的关联信息 |
| `quality` | `1`：最终输出明确改善；`0`：无明显变化；`-1`：退化或明显副作用；`uncertain`：不能判断 |
| `large_scale_error` | `yes` / `no` / `uncertain`，检查明显增删、移动、裁剪、拉伸和内容重绘 |
| `false_accept` | C/D 中在线接受却人工认为不应接受填 `yes`；明确无误接受填 `no`；无法判断填 `uncertain`；A/B 填 `NA` |
| `false_reject` | C/D 中至少一个被拒候选其实质量改善且内容保持，填 `yes`；检查完候选且无此情况填 `no`；无法判断填 `uncertain`；A/B 填 `NA` |
| `notes` | 写明对象、区域、候选文件名和判断依据，不仅写“好/不好” |

这里的 `false_reject` 是任务级“包含误拒绝候选”标记。若需要候选级误拒绝率，应另建候选标注表；不能直接把任务级标签当作候选级统计。

原图回退通常质量为 `0`，但仍应实际查看。物体细节、文字或身份是否保真不能只看检测框；同时也不能将正确的去噪纹理变化一概判为错误重绘。难以判断时保留不确定。

尽量固定观察尺度和判定标准，避免只看系统给出的接受结论。条件允许时，让复核者先看匿名编号图片再看组别和程序理由，减少预期影响；当前没有实现自动盲评界面，不声称历史结果已经过盲评。

## 13. 报告中如何使用结果

自动表可以报告调用、耗时、自动接受和工具使用情况。人工表未填写前，人工大尺度错误率、误接受和误拒绝必须保持待复核。

本轮 A/B 没有尺寸对应的生成输出可计算 PSNR/SSIM，C/D 的可计算子集包含大量原图回退。应明确披露样本组成，不能用这些子集均值对四组做直接排名。

人工复核完成后，将标注副本与审核口径另行归档，再撰写人工结果分析。当前 `report.py` 不读取人工标签；在它生成的 `实验记录.md` 中手工加入的内容，下一次生成也会被覆盖，应单独保存人工分析文档。

## 14. 每轮应留下什么

- 轮次 ID、源码与脚本快照、依赖锁文件、权重与作者代码来源和哈希。
- 样本清单、配对检查、校准记录与冻结配置。
- 48 行结果或明确标注的不完整结果，以及引用的全部任务目录。
- 原图、候选、最终输出、指令、结构检查、VLM 结论、路线与次数事件。
- 自动报告、已填写的人工标注副本及人工分析；执行失败和无法确认样本也要保留。

归档与分享时排除 `api.txt`、`.env`、认证头和带签名下载 URL。不把工程测试通过、生成成功、在线接受、离线接受和人工确认混为同一个结论。
